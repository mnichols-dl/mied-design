# FDD ↔ SDD Tag Index

Aggregated, queryable list of every FDD-to-SDD tag produced across all completed
reviews. Each row here should also exist in the source review's Section 4 (Tagging) —
this file exists so the mapping can be scanned/searched in one place without opening
every individual review file, and so it can eventually be cross-checked against (or
folded into) the `eng/*.ttl` graph as a `Requirement`/traceability layer.

Add a row every time a review's Tagging section is filled in. Do not remove rows when a
review's status changes — instead update the Relationship column if it changes (e.g.
a "gap" becomes "implements" once the SDD is updated to cover it).

## Column conventions

- **Source Reference** — `<source-doc-path-or-number> §<section/heading>`, matching the
  tagging format defined in [README.md](README.md). Use the client's folder number
  (e.g. `01 - User Management`, `15.4`) as shorthand; fall back to the full relative path
  when the number alone is ambiguous.
- **Domain(s)** — one or more `solution-areas/` folder names. List all that apply for
  cross-domain items (comma-separated).
- **Aggregate / Permission / Sequence** — the specific target where possible (an
  aggregate name from a `-domain.md`, a permission ID from a `-permissions.md`, or a
  flow name from a `-sequences.md`). If the tag is at the whole-domain level rather than
  a specific target, write "domain-level."
- **Relationship** — one of: `implements`, `conflicts with`, `gap — not yet modeled`,
  `duplicates`, `informs open question #N` (reference the review's Open Questions
  table), or a short `resolved — <what was decided>` once a discrepancy is settled.
- **Review** — link to the review file this tag came from.

## Querying this file

Until this grows large enough to warrant tooling, treat it as a flat table: use your
editor's search/filter, or sort by Domain to see everything tagged against a given
solution area at once. If it does grow large, splitting per-domain (`tag-index-iam.md`,
etc.) or generating this file from the review records is a reasonable next step — flag
it if manual upkeep becomes a burden.
