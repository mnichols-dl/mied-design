# Client Questions — Consolidated Tracker

A flat, prioritized list of every open question raised **to the client** across all FDD
reviews, pulled from each review file's "Open Questions Raised by This Review" table.
This is the list to work from when prepping for a client conversation — the full
reasoning/citations for each question live in the linked review file; this table exists
so you don't have to open every review to see what's outstanding.

Internal-only open questions (ones resolvable within the team, not requiring the client)
stay in their review file's Open Questions table and are **not** duplicated here.

## How to use this — be judicious

Not every `Raised To: Client` row in a review's Open Questions table belongs here. This
list is for the client's time — a long list is a list nobody works from. Add a row only
when it clears a real bar:

- **It genuinely needs the client**, not just a careful re-read of their own documents.
  An FDD-vs-itself contradiction the team can resolve by picking the internally-consistent
  reading (and just confirming that guess later) usually doesn't need its own row — only
  add it if both readings are equally plausible and getting it wrong is costly.
  Similarly, don't add a question this repo's own docs can already answer with more
  reading (check before asking).
- **It's actually blocking something**, not merely interesting. If the answer doesn't
  change what gets built or how, or a reasonable default lets work continue without a
  client answer, it doesn't need to sit on the client's list.
- **It's been sharpened, not raw.** Don't transcribe a review's Open Question verbatim —
  distill it to the one thing the client needs to decide, the way the Staffing Agency
  entry above was narrowed from "what is this concept" down to the one EEM fact that
  actually resolves it. If a question can't be asked in a sentence or two, it probably
  needs more internal digging before it's ready for the client, not a spot on this list.

When in doubt, leave it in the review file's own Open Questions table and revisit later —
it's easy to promote a question here once it's clearly load-bearing; it's costly to walk
back a list the client has started expecting to be worth their attention.

- Set **Priority** by how much design/build work is stalled behind the answer —
  `Immediate` for anything actively blocking a decision you're about to make;
  `High` for foundational modeling questions; `Normal` for everything else.
- When answered, fill in **Client Answer / Decision** and the date, set Status to
  `Answered`, and update the source review file's own Open Questions table and any
  affected Discrepancy/Coverage Gap rows to match (this tracker doesn't replace fixing
  the review — it's the pointer that reminds you to go do it).
- Keep answered rows here (struck through or marked) rather than deleting — it's useful
  history of what's already been settled with the client.
