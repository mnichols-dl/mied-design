## Summary

This is the first review of the `proflearning` domain, and the FDD folder is the messiest
encountered in this series — a current, locked FDD (14 - Admin) sitting alongside eight
files of pre-consolidation legacy MORE-system material and a `.url` shortcut. Tier 2 triage
confirmed the `Old- Professional Learning/` subtree is genuinely superseded (spot-checked
against the current doc — same narrative, earlier draft, no content the current FDD dropped)
and most of the loose planning documents are the same: brainstorming, wishlists, and
requirements drafts for the legacy MOECS/MORE system, not live specifications. One
exception was promoted out of Tier 2: `Professional Learning Process Steps.md` documents
statutory PD obligations (MCL 380.1526 "New Teacher" 15-day requirement, MCL 380.1527
5-day-for-all-staff requirement) that never made it into the current FDD 14 or
`proflearning-domain.md` — a real, if narrow, coverage gap. The domain's core SCECH model
holds up well against the current FDD 14 and largely against the two SCECH-specific
documents, with one clean gap (a "College Conversion" program type and its own SCECH
conversion formula, distinct from the modeled STARR-based `CollegeCourseCredit` path) and
a repeat of a pattern seen in the EPP review (FDD 13's Addendum 13.6): this FDD's own
Addendum contradicts its main narrative on whether file-queue management is an admin
capability. The most consequential finding, however, is not sourced from the FDD text at
all — it surfaced from this review's mandated cross-domain check of credentialing's IDP
business rule: `proflearning-domain.md` has **no `IndividualDevelopmentPlan` aggregate
whatsoever**, `proflearning-api.yml` has no `/idp` endpoint, and `credentialing-domain.md`'s
detailed IDP validation rule (which calls a Professional Learning endpoint that doesn't
exist) doesn't even agree with `credentialing-sequences.md`'s own "Renew Credential"
sequence, which treats IDP as a manually-uploaded document with no API call at all. A
second, same-shape cross-domain wiring gap was found alongside it: the same sequence's
SCECH-hours check calls an endpoint (`GET /scech-hours`) that also doesn't exist in
`proflearning-api.yml`, and conflicts with `proflearning-domain.md`'s own stated design
(Credentialing should maintain a running balance from subscribed events, not query live).
Both are recorded as Discrepancy #1 below and flagged directly in all three affected SDD
files rather than resolved unilaterally, since building the missing IDP aggregate is real
proflearning-domain design work, not a same-review fix.

## Process/Template Friction Noted

- **The "Old-" archive-folder pattern triaged cleanly and is worth formalizing for future
  reviews of this corpus.** This review confirms the task's hypothesis: an `Old-`-prefixed
  subfolder's main document (here, `Professional Learning (14.0).md`) can be spot-checked
  against the current top-level FDD in a few minutes (same narrative, shorter/earlier draft,
  no content the current doc dropped), and once that single spot-check confirms
  supersession, the remaining sub-files in the same `Old-` tree can be triaged fast by
  skimming for legacy-system screen/ADO-story detail (recognizable by MORE-era artifacts:
  ADO work-item links, "MOECS" terminology, un-styled wireframe descriptions, empty
  "Reviewers/Approvers" sign-off tables). All 6 tracked sub-files here matched that
  signature. Recommend this exact two-step triage (spot-check the folder's own top-level
  doc first, then pattern-match the rest) as the standard playbook the task description

- **A genuinely load-bearing finding came from a document with no formal status at all** —

- **The IDP/SCECH-hours finding (Discrepancy #1) is a different shape of finding than this

  primary FDD folder said anything about it. It turned out to be the review's most

  standing step in future reviews with a named cross-domain integration point in the brief:
