Rough notes:
- Worklists is a term used by the stakeholders to describe what appears to be a general UI pattern that organizes items that need a user's attention.
- They use language that describe "worklists" as objects, like "add to worklist" or "view worklist", however we see it beneficial to look at this as more of a UI pattern.
- To enable a "worklist" type of UI component, the data must be retrievable from an API in a manner that supports the appropriate filtering. For example, `GET /api/applications?status=pending`. This is not a well-established pattern yet, but it portrays the way a "worklist" might be retrieved and displayed. The UI component in particular that is rendering these pending applications would then have some call to action, like an ability to click in to the specific application to process it. It would also be ideal to support sorting and searching. Sorting may be useful to show "oldest" or "longest waiting" items as a means for prioritization. Searching may be helpful to simply find a particular application.
- Much of this functionality may already be expected or needed for other purposes in the API design. As such, it would be worth just noting what the requirements are anytime a "worklist" is mentioned -- to think about how an API may be shaped to facilitate this UI pattern of "worklists".
