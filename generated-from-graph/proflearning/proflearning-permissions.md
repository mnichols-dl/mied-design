# Professional Learning - Permissions Catalog (DRAFT)

This document defines all atomic permissions for the Professional Learning domain.

---

## Permissions

| Category                  | Permission ID                            | Description                                                     | Applicable Scopes               | Notes                                                                                                |
| ------------------------- | ---------------------------------------- | --------------------------------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Sponsor Management**    | `proflearning.sponsor.view`              | View sponsor details and program list                           | Entity (specific sponsor)       | Entity resolves to a specific sponsor. Coordinators have this for their own sponsor.                 |
| **Sponsor Management**    | `proflearning.sponsor.edit`              | Edit sponsor contact information and metadata                   | Entity (specific sponsor)       | Coordinators for their sponsor, admins system-wide. No distinct 'update sponsor' API operation exists in proflearning-api.yml (only GET /sponsors/{sponsorId}) — the proflearning-domain.md aggregate description says MiEdWorkforce 'edits contact info' but no corresponding endpoint was found; an honest gap, left with no PermissionRequirement. |
| **Sponsor Management**    | `proflearning.sponsor.approve`           | Approve new sponsor applications                                | System-wide                     | Professional Learning Admin only. GENUINE GAP, already flagged in proflearning-domain.ttl's own aggregate design note and plrn:Question_SponsorApprovalWorkflowContradiction (Open Question #9): the ProfessionalLearningSponsor aggregate says sponsor creation is EEM-only with no PendingApproval state inside MiEdWorkforce, yet this permission — and FDD 26's described new-Sponsor application / Lead-Administrator e-signature workflow — presumes such a workflow exists. No SponsorApplication aggregate or API operation is modeled for it (proflearning-api.yml has no sponsor-application endpoints at all); left with no PermissionRequirement as an honest, documented gap rather than fabricating the missing workflow. |
| **Sponsor Management**    | `proflearning.sponsor.delete`            | Delete sponsor applications or approved sponsors                | System-wide                     | Professional Learning Admin only. No DELETE/deactivate sponsor endpoint exists in proflearning-api.yml at all — same class of gap as sponsor.approve above, compounded by the aggregate's own Design Note that sponsor lifecycle (creation, presumably deletion) belongs to EEM, not MiEdWorkforce. Left with no PermissionRequirement. |
| **Program Management**    | `proflearning.program.create`            | Submit new program applications                                 | Entity (sponsor-scoped)         | Entity resolves to sponsor-scoped. Coordinators for their sponsor.                                   |
| **Program Management**    | `proflearning.program.edit`              | Edit program details (triggers re-approval if approved)         | Entity (program-scoped)         | Coordinators for programs under their sponsor                                                        |
| **Program Management**    | `proflearning.program.view`              | View program application details                                | Entity (program-scoped)         | Entity resolves to program-scoped; coordinators, admins, or public for active programs. Backs listProgramApplications, getProgramApplication, listPrograms, and getProgram (internal-user access pattern) — matches proflearning-api.yml's x-permissions-required exactly. |
| **Program Management**    | `proflearning.program.approve`           | Approve program applications                                    | System-wide                     | Professional Learning Admin only. Backs approve, reject, and request-info — matches proflearning-api.yml exactly. |
| **Program Management**    | `proflearning.program.withdraw`          | Withdraw or delete programs                                     | Entity (program-scoped)         | Entity resolves to program-scoped. Coordinators for their programs, admins system-wide.              |
| **Session Management**    | `proflearning.session.create`            | Add program sessions (dates/locations)                          | Entity (program-scoped)         | Coordinators, Professional Learning Admin                                                            |
| **Session Management**    | `proflearning.session.edit`              | Edit session dates and locations                                | Entity (session-scoped)         | Coordinators, Professional Learning Admin                                                            |
| **Attendance Management** | `proflearning.attendance.add`            | Add attendees to program roster                                 | Entity (session-scoped)         | Coordinators for their programs                                                                      |
| **Attendance Management** | `proflearning.attendance.view`           | View attendance roster                                          | Entity (session-scoped)         | Entity resolves to session-scoped; coordinators for their programs, admins system-wide.              |
| **Attendance Management** | `proflearning.attendance.adjust`         | Adjust awarded SCECH hours before certification                 | Entity (session-scoped)         | Coordinators for their programs                                                                      |
| **Attendance Management** | `proflearning.attendance.certify`        | Certify finalized attendance and award SCECHs                   | Entity (session-scoped)         | Coordinators for their programs                                                                      |
| **Attendance Management** | `proflearning.attendance.override`       | Adjust SCECH hours after certification                          | System-wide                     | Professional Learning Admin only. GAP: no API operation is gated by this permission specifically — post-certification adjustment is instead handled entirely through the SCECHCorrectionRequest workflow (submitCorrectionRequest / approveCorrectionRequest / denyCorrectionRequest), gated by the distinct proflearning.correction.* permissions. This permission appears to describe the same capability the correction-request workflow already provides, under a different name; left with no PermissionRequirement rather than double-gating approveCorrectionRequest under two permission IDs. |
| **Evaluation Management** | `proflearning.evaluation.view`           | View submitted evaluations                                      | Entity (program-scoped)         | Coordinators, Professional Learning Admin                                                            |
| **Evaluation Management** | `proflearning.evaluation.submit`         | Submit program evaluation                                       | Self-only                       | Attendees for programs they attended. SIGNIFICANT GAP: neither proflearning-api.yml (no evaluation-submission endpoint) nor proflearning-sequences.md (no 'Attendee Submits Evaluation' sequence, despite the EvaluationTemplate aggregate's own 'Referenced In' list naming one) actually models this capability end-to-end, even though the domain doc's certification workflow (plrn:Rule_EvaluationRequirementProgramSpecific) depends on evaluations being submitted before certification can proceed. Left with no PermissionRequirement — a real, load-bearing gap, not a minor one. |
| **College Course Credit** | `proflearning.collegecourse.apply`       | Apply college course for SCECH credit                           | Self-only                       | Educators for their own courses. Backs getEligibleCollegeCourses and applyCollegeCourse.             |
| **Admin Functions**       | `proflearning.admin.categories`          | Manage program categories and subcategories                     | System-wide                     | Professional Learning Admin. Backs listProgramCategories, createProgramCategory, updateProgramCategory, createSubcategory, deactivateProgramCategory. |
| **Admin Functions**       | `proflearning.admin.questions`           | Manage evaluation question sets                                 | System-wide                     | Professional Learning Admin. LIKELY-STALE / GAP: proflearning-domain.md's own Scope section explicitly says the Question Set framework is a cross-cutting capability this domain does NOT own, and no API operation in proflearning-api.yml is gated by this permission — evaluation-templates endpoints are gated by the separate proflearning.admin.evaluationtemplates instead, which only lets an admin select existing question-set IDs, not manage question content itself. Left with no PermissionRequirement. |
| **Public Access**         | `proflearning.catalog.search`            | Search public professional learning catalog                     | System-wide (unauthenticated)   | Unauthenticated; no login required. Consistent with searchCatalog's x-permissions-required: [] in proflearning-api.yml and plrn:Op_SearchCatalog's sd:requiresAuth false — no PermissionRequirement is modeled for that operation since ApiOperationRequiresPermissionShape only applies to non-public operations and searchCatalog is genuinely external-public with zero permission gating. |
| **Public Access**         | `proflearning.catalog.bookmark`          | Bookmark programs/sponsors                                      | System-wide (authenticated)     | Requires login (System-wide (authenticated) per the source). Backs listBookmarks, createBookmark, deleteBookmark. |
| **Correction Requests**   | `proflearning.correction.submit`         | Submit SCECH correction request for certified attendance        | Entity (session-scoped)         | Entity resolves to session-scoped; coordinators for their programs. Backs submitCorrectionRequest. Scoped to coordinators only — FDD 27 describes a distinct educator-initiated correction/dispute pathway with no corresponding permission here; see plrn:SCECHCorrectionRequestAggregate's notes and plrn:Question_EducatorInitiatedCorrectionPathway (Open Question #11). |
| **Correction Requests**   | `proflearning.correction.view`           | View correction requests                                        | Entity (sponsor/session-scoped) | Entity resolves to sponsor/session-scoped; coordinators see their own requests, admins see all. Backs listCorrectionRequests. No single-resource GET /correction-requests/{id} exists in proflearning-api.yml (see plrn:Op_ListCorrectionRequests's own notes) — the list endpoint plus this permission is the only modeled coverage. |
| **Correction Requests**   | `proflearning.correction.approve`        | Approve SCECH correction requests                               | System-wide                     | Professional Learning Admin only. Backs approveCorrectionRequest and denyCorrectionRequest.          |
| **Admin Functions**       | `proflearning.admin.evaluationtemplates` | Manage evaluation templates                                     | System-wide                     | Professional Learning Admin. Backs listEvaluationTemplates, createEvaluationTemplate, updateEvaluationTemplate. |
| **Reports**               | `proflearning.report.view`               | View and export all professional learning reports and analytics | System-wide                     | Includes export; Professional Learning Admin                                                         |
