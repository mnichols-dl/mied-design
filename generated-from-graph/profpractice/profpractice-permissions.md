# Professional Practice Review - Permissions Catalog

This document defines all atomic permissions for the Professional Practice Review domain.

---

## Permissions

| Category               | Permission ID                      | Description                                                                 | Applicable Scopes                         | Notes                                                                                                |
| ---------------------- | ---------------------------------- | --------------------------------------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Self-Disclosure        | `profpractice.disclosure.submit`   | Submit self-disclosure of criminal conviction or disciplinary action        | Self-only                                 | All authenticated educators                                                                          |
| Self-Disclosure        | `profpractice.disclosure.view`     | View disclosure history and status                                          | Self-only, System-wide, Worklist-specific | Educators see own; reviewers see assigned/all. Source lists 'Worklist-specific' as a third applicable scope — see file header note on the Worklist-specific scope-vocabulary gap; scope:AssignedOnly is the closest existing proxy. |
| PPR Response           | `profpractice.response.submit`     | Submit annual Professional Practice Review response                         | Self-only                                 | All authenticated educators; required annually                                                       |
| PPR Response           | `profpractice.response.view`       | View PPR response history                                                   | Self-only, System-wide                    | Educators see own; admins see all                                                                    |
| Disclosure Review      | `profpractice.disclosure.search`   | Search and filter disclosures across worklists                              | System-wide, Worklist-specific            | PPR Reviewer role; includes advanced filters. Source lists 'Worklist-specific' as an applicable scope — see file header note. |
| Disclosure Review      | `profpractice.disclosure.edit`     | Edit disclosure details during active review                                | System-wide, Worklist-specific            | Can modify date, type, description, attachments while status is 'Under PPR Review'. Source lists 'Worklist-specific' as an applicable scope — see file header note. |
| Disclosure Processing  | `profpractice.status.update`       | Change disclosure status through workflow                                   | System-wide, Worklist-specific            | PPR Reviewer role; enforce valid status transitions. Source lists 'Worklist-specific' as an applicable scope — see file header note. profpractice-sequences.md's 'Review Disclosure and Update Status' sequence header instead names the permission id 'profpractice.disclosure.update-status', which does not exist in this catalog — a genuine documented naming discrepancy between the two source documents, left unresolved rather than silently reconciled. |
| Disclosure Processing  | `profpractice.remarks.add`         | Add comments to disclosures (internal or external)                          | System-wide, Worklist-specific            | PPR Reviewer role; remark type determined by API parameter. Source lists 'Worklist-specific' as an applicable scope — see file header note. |
| Disclosure Processing  | `profpractice.disclosure.finalize` | Mark disclosure as reviewed and lock for editing                            | System-wide, Worklist-specific            | Transitions to 'Reviewed-*' status; prevents further edits. Source lists 'Worklist-specific' as an applicable scope — see file header note. |
| Disclosure Processing  | `profpractice.disclosure.revert`   | Revert finalized disclosure back to "Under PPR Review"                      | System-wide                               | PPR Admin role only; allows corrections after finalization. No API operation or sequence currently models this permission — profpractice-api.yml has no revert endpoint and no sequence exercises it; a documented gap, not modeled with a PermissionRequirement. |
| Disclosure Deletion    | `profpractice.disclosure.delete`   | Remove disclosure from view but retain in audit (soft delete)               | System-wide                               | PPR Admin role only; educator cannot delete own disclosures. No API operation or sequence currently models this permission — profpractice-api.yml has no disclosure-delete endpoint; a documented gap. |
| Account Markers        | `profpractice.markers.view`        | View account-level markers (Mandatory Hold, Enhanced Monitoring, Re-Review) | System-wide, Entity, District, ISD        | PPR Reviewer can view; visibility by scope                                                           |
| Account Markers        | `profpractice.markers.manage`      | Set or clear any account marker type                                        | System-wide                               | PPR Admin or Credentialing Admin role; requires justification; fully audited. profpractice-sequences.md's 'Manage Account Markers' sequence instead names finer-grained permission ids per marker (account-marker.set-mandatory-hold, account-marker.clear-mandatory-hold, account-marker.set-enhanced-monitoring, account-marker.set-rereview), none of which exist in this catalog — a genuine documented naming discrepancy, left unresolved rather than silently reconciled or split into new permissions. |
| Assessments            | `profpractice.clearance.view`      | View PPR clearance assessment for credential applications                   | System-wide, Entity, District, ISD        | Credentialing staff check clearance before approval                                                  |
| Assessments            | `profpractice.eligibility.view`    | View roster eligibility assessment for employment                           | System-wide, Entity, District, ISD        | District HR checks eligibility before roster addition                                                |
| External Integration   | `profpractice.rapback.view`        | View Rap Back notification metadata                                         | System-wide                               | PPR Reviewer role; see notification date, TCN, judicial marker                                       |
| External Integration   | `profpractice.rapsheet.retrieve`   | Initiate on-demand rap sheet retrieval via CHRISS SOAP call                 | System-wide                               | PPR Reviewer role; display-only, never stored. profpractice-sequences.md's 'Retrieve Full Rap Sheet for Review' sequence header instead names 'profpractice.rapback.retrieve-rapsheet', which does not exist in this catalog — a genuine documented naming discrepancy. |
| External Integration   | `profpractice.nasdtec.view`        | View NASDTEC disciplinary records matched to educators                      | System-wide                               | PPR Reviewer role; includes clearinghouse URL                                                        |
| External Integration   | `profpractice.nasdtec.access`      | Access external NASDTEC clearinghouse site for full details                 | System-wide                               | PPR Reviewer role; opens clearinghouse URL in new tab. No API operation models this permission — it gates an outbound browser navigation, not a MiEdWorkforce endpoint; a documented, expected non-gap. |
| Audit                  | `profpractice.actions.log`         | Document external activities (phone calls, emails, manual reviews)          | System-wide, Worklist-specific            | PPR Reviewer role; creates audit trail for offline actions. Source lists 'Worklist-specific' as an applicable scope — see file header note. profpractice-sequences.md's 'Log Non-System Action' sequence header instead names 'profpractice.disclosure.log-non-system-action', which does not exist in this catalog — a genuine documented naming discrepancy. |
| Audit                  | `profpractice.audit.view`          | View disclosure and marker audit logs                                       | System-wide, Entity, District, ISD        | Scope-aware audit visibility. No API operation or sequence currently models this permission — profpractice-api.yml has no dedicated audit-log endpoint; a documented gap. |
| Worklist Management    | `profpractice.worklist.view`       | View assigned PPR worklists and queued disclosures                          | Worklist-specific                         | PPR Reviewer assigned to specific worklists. Source lists this scope as 'Worklist-specific' — see file header note; scope:AssignedOnly is the closest existing proxy. |
| Worklist Management    | `profpractice.worklist.configure`  | Create, edit, or pause PPR worklists and routing rules                      | System-wide                               | PPR Admin role only                                                                                  |
| Worklist Management    | `profpractice.worklist.assign`     | Add or remove reviewers from worklists                                      | System-wide                               | PPR Admin role only. No dedicated API operation models this permission separately — profpractice-api.yml's PUT /worklists/{worklistId} (assignedReviewerIds field of WorklistCreate schema) is the closest match but is gated by profpractice.worklist.configure, not this permission; a documented gap between the permissions catalog's granularity and the API's actual gating. |
| Question Configuration | `profpractice.questions.view`      | View PPR question configurations and branching logic                        | System-wide                               | Read-only access to form definitions                                                                 |
| Question Configuration | `profpractice.questions.manage`    | Create, edit, or activate PPR question configurations                       | System-wide                               | System Admin only; creates versioned changes. No API operation currently models this permission — profpractice-api.yml only exposes GET endpoints for question configuration (getDisclosureQuestions, getPprQuestions), no create/update/activate endpoint; a documented gap. |
| Documents              | `profpractice.attachments.view`    | View supporting documents attached to disclosures                           | System-wide, Worklist-specific, Self-only | Educators see own; reviewers see assigned disclosures. Source lists 'Worklist-specific' as an applicable scope — see file header note. Not modeled with a PermissionRequirement here: document retrieval for a disclosure is a Documents-capability call (GET /documents?disclosureId=...) shown in profpractice-sequences.md, not one of profpractice's own ApiOperations. |
| Documents              | `profpractice.attachments.upload`  | Upload supporting documents to disclosure                                   | Self-only                                 | Educators upload to their own disclosures during submission. Not modeled with a PermissionRequirement here for the same reason as profpractice.attachments.view — the upload call (POST /upload) belongs to the Documents capability's own API, not profpractice's. |
| Documents              | `profpractice.attachments.delete`  | Remove document from view but retain in audit (soft delete)                 | System-wide                               | PPR Reviewer role; requires justification. Same Documents-capability-ownership reasoning as profpractice.attachments.view/.upload — no PermissionRequirement modeled here. |
| Reporting              | `profpractice.report.view`         | View and export all PPR reports, metrics, and analytics                     | System-wide, Entity, District, ISD        | Scope-aware; includes export. profpractice-sequences.md's 'Generate PPR Compliance Report' sequence header instead names 'profpractice.reports.disclosure-metrics.view' or 'profpractice.reports.compliance.view', neither of which exists in this catalog — a genuine documented naming discrepancy. |
| District Notifications | `profpractice.notifications.view`  | View PPR-related notifications for district users                           | District, ISD                             | District HR sees alerts for educators they're hiring/employing. No API operation or sequence currently models this permission — profpractice-api.yml has no district-notifications endpoint; a documented gap. |
